A 12B-parameter model (Krea 2 RAW) does not fit in 12GB. The trick everyone uses is FP8 weight compression plus pushing most of the model into system RAM and streaming it back for each step. That is why 12GB works and why 16GB of RAM is your weak link: the model lives there while it trains.

  • Do this first: set a 64GB Windows pagefile on the SSD (System → Advanced → Performance → Virtual memory). It is the difference between a crash and a slow night.
  • Close everything else while training. Browser tabs eat the RAM the model needs.
  • Expect 4–9 hours for one character on this card. Leave it running overnight.
  • If it thrashes or OOMs, fall back to FLUX.1 dev, which is the comfortable 12GB path and still photoreal at rank 16–32.

The pipeline, in order

  • 1 · Seed the character. One photoreal portrait you actually believe. Everything inherits its flaws, so refuse anything plasticky here.
  • 2 · Build 30–40 shots of that same face (angles, outfits, light, framing). The dataset is where consistency is actually decided.
  • 3 · Cull hard. One drifted jaw or wrong eye colour teaches the model to be inconsistent. Delete it.
  • 4 · Caption only what changes (framing, pose, outfit, light, background). Never the face, hair or body: those must stay welded to the trigger word.
  • 5 · Train on Krea 2 RAW, render on Krea 2 Turbo at 0.75–0.85 strength.
  • 6 · Prompt like a photographer, not like an AI. Camera, lens, light, grain, pores.

The Dataset tab builds the exact shot list. The Captions tab writes the .txt files. The Train tab gives you the command line and the settings. Generate gives you the prompt.

Rules that decide whether this works

  • Resolution: every image at least 1024px on the long edge. Soft source, soft face.
  • Same face, different everything else. 6 lighting setups, 3 outfits, 3–4 backgrounds, all dull and different.
  • Mix framings: close-up, waist-up, full body. A LoRA trained only on portraits cannot shoot a full body.
  • Not all standing: sitting, walking, crouching, in a car, seen from behind.
  • No beauty filters, no upscaling, no smoothing. Grain is your friend; it is the main thing that reads as "photograph".
  • 20–40 images total for the character, 10–20 of them face-focused. More than 40 and it starts averaging.

Caption files

One .txt per image, same filename as the image. These are generated from the shot list: edit any slot in the Dataset tab and the caption updates here.

Caption only what changes. Framing, pose, outfit, light, background. Never the face, hair, age or body: constant things must be absorbed by the trigger word, or the LoRA stops being one person.

Good vs bad caption

Bad: ohwx, a beautiful woman with curly dark hair, freckles, hazel eyes, standing in a cafe

That teaches the model that "curly dark hair" is optional at inference. Drop the identity words.

Good: ohwx, waist-up portrait, seated at a table, wearing a cream knit sweater, soft window light from the left, blurred cafe interior

Same person every time, while pose, clothing and light stay controllable.

Pick your path

Krea 2 RAW is the most photoreal open model for people, and it does run on a 3060 12GB — at 512px, rank 16, with block swapping. It is the tightest fit of the three.

FLUX.1 dev is the comfortable 12GB path and has the biggest LoRA ecosystem. Slightly less photoreal than Krea 2 out of the box, easy to fix with prompt and strength.

Train on the RAW/base checkpoint, render on the fast distilled one. That division works cleanly: identity transfers, speed stays.

FLUX.1 dev on 12GB — AI Toolkit

The easier path. Web UI on localhost:8675, no command line needed. Paste this YAML into a new job.

job: extension
config:
  name: "character_v1"
  process:
    - type: 'sd_trainer'
      training_folder: "C:/aitk/output"
      device: cuda:0
      network:
        type: "lora"
        linear: 16
        linear_alpha: 16
      save:
        dtype: float16
        save_every: 250
        max_step_saves_to_keep: 8
      datasets:
        - folder_path: "C:/dataset/character"
          caption_ext: "txt"
          caption_dropout_rate: 0.05
          shuffle_tokens: false
          cache_latents_to_disk: true
          resolution: [512]
      train:
        batch_size: 1
        steps: 2000
        gradient_accumulation_steps: 1
        train_unet: true
        train_text_encoder: false
        gradient_checkpointing: true
        noise_scheduler: "flowmatch"
        optimizer: "adamw8bit"
        lr: 4e-4
        dtype: bf16
      model:
        name_or_path: "black-forest-labs/FLUX.1-dev"
        is_flux: true
        quantize: true
      sample:
        sampler: "flowmatch"
        sample_every: 250
        width: 1024
        height: 1024
        prompts:
          - "ohwx, waist-up portrait, soft window light, natural skin texture"
        neg: ""
        seed: 42
        walk_seed: true
        guidance_scale: 4
        sample_steps: 25

quantize: true is what lets this fit. 2000 steps ≈ 3–5 hrs on a 3060. Raise resolution to 768 only if you have VRAM to spare.

The catch, and why FLUX

A T4 is a 2018 card: no FP8, no bf16. So the Krea 2 trick (compress the 12B model to FP8) does not exist on Kaggle. What does work is quantising FLUX.1 [dev] to 4-bit (NF4) and training rank 32 at 1024px in it — about 11GB of VRAM, which fits a single T4 with room to spare.

FLUX.1 [dev] is slightly less photoreal than Krea 2 straight out of the box, and it is the difference between free and not free. Photorealism still comes mostly from your dataset and your prompts, which is the part you control.

Licence: FLUX.1 [dev] is non-commercial. Fine for a personal character; check the licence before you sell anything built on it. FLUX.1 [schnell] is Apache-2.0 but weaker at holding a face.

Run it, in order

  • 1 · Kaggle account + phone verification. No verification, no GPU.
  • 2 · Notebook settings: Accelerator GPU T4 x2, Internet On.
  • 3 · Hugging Face: free account, open the FLUX.1-dev model page, accept the licence (it is gated per repo), then make a Read token.
  • 4 · Kaggle secret: Add-ons → Secrets → new secret HF_TOKEN → paste the token → attach.
  • 5 · Dataset: upload your images and their .txt captions as a private Kaggle Dataset, then Add input to the notebook.
  • 6 · Upload the notebook (flux-lora-kaggle.ipynb) via File → Import Notebook, set the dataset slug in the loader cell, then Run all.

Trigger word: this trainer prepends the trigger itself. Export your captions with the trigger off (the checkbox in the Dataset tab) and set the token once in the notebook config. Twice in a caption is worse than not at all.

If the repo drifts from Kaggle's current image, the same job runs locally on your 3060 with --quantize nf4, or on kohya / AI Toolkit. The dataset and captions do not change.

Only a browser? That is enough

Nothing in this path installs anything. Kaggle, Hugging Face and this app are all websites, so an old office PC with Intel graphics runs the whole thing from a tab. The GPU you train on belongs to Kaggle, not to you.

Step 0 — you still need seed images. 20–40 shots of one face, before any training. You can make those on Kaggle too: SDXL at 1024px on a T4 is a few seconds per image, so 40 shots costs minutes of the same weekly quota. The notebook seed-faces-kaggle.ipynb does this end to end — 64 candidates, a numbered contact sheet, then the img2img pass that rebuilds your 36-shot set with captions.

  • Generate wide, then narrow. Make 60–80 candidates in a notebook, pick the 6–8 that look like an actual photograph of an actual person, then rebuild the set from those with image-to-image at low strength so the face stays put.
  • Never build the set from the weakest seed. The seed's realism is the ceiling for everything after it: if the starting face is plasticky, the LoRA learns plastic.
  • Then run the training notebook on that set, same free quota.

On a work machine: use a personal Kaggle and Hugging Face account, never the work one. Nothing is installed, nothing is saved to that PC's disk, and the only files involved are your own character images — keep work documents out of the Kaggle dataset.

Intel integrated graphics can technically run Stable Diffusion through OpenVINO, at roughly half a minute per image and with a quality ceiling well below FLUX. On an office machine that usually means no admin rights anyway — not worth it when the free tab path is better.

Realism controls

0.80

If the face gets glassy or over-sharp, go down, not up. Strength 0.8 plus a proper photo prompt beats 1.0 every time.

Prompt builder

The fixed tail is the important part: natural skin texture, visible pores, slight asymmetry, no makeup filter, true-to-life colour. Keep it on every prompt.

Never put these in a prompt

perfectflawlessstunninghyperrealistic8kmasterpiecebeautifuldetailed skinultra sharp

They are the AI look you are trying to escape. They push the model toward airbrushing. "Slight asymmetry" and "visible pores" push the other way.

Test prompts — run all five before you trust it

If the face survives these, it will survive a feed. If it breaks on any of them, add that case to the dataset and retrain.

  • Harsh sun: hard shadows across the face, squinting. Kills over-smoothing instantly.
  • Dark bar: one lamp, high ISO, grain. Reveals a fake-looking jaw and plastic eyes.
  • Mirror selfie: phone flash, bathroom, arm raised. The most common Instagram format, and the easiest to fail.
  • Side profile: 90°, the hardest angle for a LoRA that only saw three-quarters.
  • Wide shot: small face in a big frame. Consistency must hold with fewer pixels.
